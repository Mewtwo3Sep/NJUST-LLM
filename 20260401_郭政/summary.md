# 语义聚合无监督训练与规划器优化

【报告总结】本次分享主要围绕两条提升 LLM Agent 推理与规划能力的技术路线展开：一条是**无监督语义熵最小化推理训练**，另一条是**面向智能体的元规划器优化**。前者关注“如何在没有人工标注推理轨迹的前提下提升模型推理一致性”，后者关注“如何把规划能力从 agent 本体中解耦出来，通过单独训练规划器来稳定提升任务执行表现”。

---

## 1. EMPO：基于语义聚合的无监督推理能力提升

### 1. 动机

当前提升大语言模型推理能力的主流方法，通常依赖 **SFT + RL** 的组合流程，但这类方法有几个明显问题：

1. **强依赖监督数据**
   - 需要人工标注推理轨迹、标准答案，或者额外训练奖励模型
   - 数据构建成本高，难以扩展到更广泛任务

2. **伪标签自训练提升有限**
   - 有些方法通过 self-consistency 构造伪数据再做 SFT
   - 但性能增益有限，而且存在模型坍缩风险

3. **自奖励 RL 仍然依赖验证器**
   - 即使是自生成数据做强化学习，通常仍要借助真实验证器或拒绝采样筛选轨迹
   - 本质上没有摆脱“外部监督信号”的依赖

因此，这项工作的核心目标是：**只使用无标注用户问题，不依赖人工答案、不依赖奖励模型，直接提升模型推理能力。**

### 2. 核心思路

论文提出 **EMPO（Entropy Minimization Policy Optimization）**，核心思想是：

- 对同一个问题采样多个回答
- 按“语义等价”而不是“表面文本一致”进行聚类
- 统计模型在不同语义簇上的概率分布
- 通过优化目标**最小化语义熵**
- 让模型更倾向于生成“能够收敛到一致答案”的推理轨迹

本质上，它不直接奖励“答对”，而是奖励“模型在潜在语义空间中的稳定收敛”。

### 3. 方法

#### 3.1 语义熵构造

对给定问题 \(q\)：

1. 从模型中采样一组输出
2. 用低成本规则进行语义聚类，例如：
   - n-gram
   - 正则表达式
   - 小模型辅助判断
3. 将每个语义簇出现的频率视作该语义的近似概率
4. 计算这些语义簇分布的熵

如果一个问题下模型的多个回答虽然表述不同，但最终都落在同一语义簇，那么熵就低；反之说明模型在“真正答案层面”不稳定。

#### 3.2 EMPO 优化目标

EMPO 通过策略优化最大化一个等价于“降低语义熵”的目标函数。

关键点在于：

- 每条输出的奖励，不是人工标签，也不是验证器打分
- 而是**该输出所属语义聚类的概率**
- 语义簇越大，说明这条推理轨迹越接近模型当前的“主语义收敛方向”

因此，EMPO 的优势函数建立在“聚类概率”之上，从而引导模型朝着低熵输出分布演化。

#### 3.3 奖励欺诈缓解：熵阈值过滤

无监督目标容易出现一个风险：

- 模型可能学会“高置信但错误”的模式
- 即过度偏向最常见语义簇，而不是形成真正严谨的推理过程

为缓解这一问题，方法里引入了**双阈值熵过滤策略**：

- **熵过高**：说明模型对该问题极不确定，样本噪声大，容易误导训练
- **熵过低**：说明模型已经很确定，继续优化收益小，反而可能加剧过度自信

因此只保留中间熵区间的样本参与优化，使训练更稳定。

### 4. 实验设置

训练与评估覆盖两类任务：

#### 数学推理
- 训练数据：NuminaMath-CoT 中随机选取 20000 条提示语
- 测试基准：
  - Minerva Math
  - MATH
  - AMC23
  - OlympiadBench
  - AIME24

#### 开放式自然推理
- 训练数据：Natural Reasoning
- 测试基准：
  - MMLU-Pro
  - GPQA

这说明 EMPO 不只针对封闭型可验证数学题，也尝试拓展到开放式高难自然推理。

### 5. 结果与结论

从汇报内容看，EMPO 的主要价值在于：

1. **真正实现了无监督推理优化**
   - 不需要标注答案
   - 不依赖额外奖励模型
   - 只靠无标注问题 + 多样本采样 + 语义聚类完成训练

2. **兼容不同任务类型**
   - 对数学推理和开放式自然推理都可适用

3. **训练目标更贴近“推理一致性”**
   - 不只是优化 token 概率，而是在语义层面压缩不确定性

不过，汇报中也提到：

- 该方法对其他模型同样可用
- 但在不同模型上的收益并不完全一致
- 例如相较于 GRPO，在千问模型上的提升似乎更明显，而在其他模型上未必同样突出

整体来看，EMPO 更像是一种**“低监督成本的推理增强框架”**，适合在缺少高质量标注数据时作为推理训练的替代方案。

## 2. MPO：面向 Agent 的元规划优化

### 1. 动机

当前很多 LLM Agent 的规划能力主要通过两种方式获得：

1. **依赖模型隐式能力**
   - 如 ReAct、Reflexion 这类方法，在执行过程中一边观察一边规划
   - 问题是容易因局部幻觉导致后续执行持续偏航

2. **依赖专家轨迹微调**
   - 如 AgentTuning、Lumos、ETO 等
   - 需要为每个 agent 单独准备数据并重新训练
   - 训练成本高，迁移性差

所以这项工作的核心问题是：

**能不能把“规划能力”从 agent 本体里拆出来，只训练一个独立规划器，用它给冻结的 agent 提供高层指导？**

### 2. 核心贡献

论文提出 **MPO（Meta-Planning Optimization）** 框架，核心思想是：

- 使用一个**独立元规划器**生成高层计划
- 将规划结果注入 agent 的提示中
- agent 本体参数保持冻结
- 只训练元规划器，而不是重新训练整个 agent

这样做的好处是：

1. 规划显式化，降低“边执行边想”导致的规划幻觉
2. 训练成本低，因为不需要改动 agent
3. 更容易迁移到不同下游任务和智能体系统

### 3. 方法

#### 3.1 SFT 冷启动

首先构造元规划器的监督微调数据：

- 使用 GPT-4o，根据任务 \(u\) 及其最佳执行轨迹 \(e\)，生成对应的高层规划 \(p\)
- 再由人工进行审核与修正
- 得到元规划器的 SFT 数据集
- 基于该数据集对元规划器进行初始化训练

这一步相当于让规划器先学会“什么样的计划是合理的”。

#### 3.2 元规划质量评估

对于给定任务和某个规划 \(p\)：

1. 把规划嵌入到 agent 的提示中
2. 让冻结的 agent 执行任务 \(N\) 次
3. 收集 \(N\) 条任务执行轨迹
4. 以任务完成率衡量该规划的质量

也就是说，**规划好不好，不是直接由语言模型判定，而是看它是否真的能帮助 agent 完成任务。**

#### 3.3 偏好优化

在完成 SFT 初始化后：

1. 对每个任务生成多个元规划
2. 通过上面的执行成功率评估每个规划质量
3. 为每个任务构造“最好规划 vs 最差规划”的偏好对
4. 对元规划器进行 DPO 微调

如果某个任务下多个规划的质量没有明显差异，则直接跳过，不纳入偏好数据。

这个过程使规划器进一步学习：**什么样的高层计划更有利于实际执行成功。**

### 4. 实验设置

实验涵盖三类典型 agent 环境：

1. **ScienceWorld**
   - 文本科学实验任务
   - 提供 0~1 稠密奖励

2. **ALFWorld**
   - 具身家务任务
   - 提供 0~1 稠密奖励

3. **WebShop**
   - 在线网页导航任务
   - 仅提供二值奖励，表示任务是否完成

元规划器模型使用 **Llama-3.1-8B-Instruct**。

### 5. 结果与结论

从报告传达出的结论来看，MPO 的价值主要在于：

1. **把规划能力显式模块化**
   - 规划不再埋在 agent 隐式推理里
   - 更适合复杂任务中的全局指导

2. **只训练规划器，显著降低成本**
   - agent 冻结，不必为每个系统重训整套模型

3. **偏好优化基于真实任务完成率**
   - 不是单纯做文本级偏好学习
   - 而是直接把“任务是否做成”作为规划优劣标准

整体上，MPO 更适合作为一种 **agent 系统级优化方法**：当底层 agent 已经具备工具使用与执行能力时，通过外挂式元规划器可以进一步改善长期任务表现。

---

## 3. 两项工作的共同启发

虽然 EMPO 和 MPO 关注的层面不同，但它们有一个共通趋势：

### 1. 从“答案监督”走向“过程优化”
- EMPO 不依赖标准答案，而是优化语义一致性
- MPO 不直接训练 agent 输出，而是优化高层规划过程

### 2. 从“模型本体强化”走向“模块化增强”
- EMPO 在训练目标上重新定义推理提升方式
- MPO 则把规划能力拆成独立模块，减少整体训练负担

### 3. Agent 训练正在从单步能力走向系统能力
- 不再只关注“会不会回答”
- 而是关注：
  - 能否稳定推理
  - 能否生成全局计划
  - 能否在执行中减少幻觉和偏航

---

## 4. 总结

这份报告展示了两类很有代表性的 Agent/Reasoning 优化方向：

- **EMPO**：解决“没有监督数据时，如何增强推理能力”
- **MPO**：解决“已有 agent 时，如何低成本增强规划能力”

前者偏向**训练范式创新**，后者偏向**系统结构创新**。

如果把它们放在更大的 Agent 发展脉络里看，可以理解为：

- EMPO 在提升 **推理层** 的稳定性与一致性
- MPO 在提升 **规划层** 的显式性与可控性

两者都说明了一件事：  
**未来 LLM Agent 的优化，不会只靠更大模型或更多监督数据，而会越来越依赖对“推理结构”“规划结构”“反馈结构”的精细设计。**
